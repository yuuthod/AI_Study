# 요약 비교

## 핵심 목적

```
┌───────────────┬────────────────────────────────────────────────┐
│     스킬      │                   핵심 목적                    │
├───────────────┼────────────────────────────────────────────────┤
│ brainstorming │ 구현 전에 아이디어를 완성된 스펙 문서로        │
│               │ 변환하는 구조화된 설계 프로세스                │
├───────────────┼────────────────────────────────────────────────┤
│ office-hours  │ YC 방식의 제품/스타트업 아이디어 검증 및 설계  │
│               │ 파트너 (2가지 모드)                            │
├───────────────┼────────────────────────────────────────────────┤
│ grill-me      │ 계획/설계를 무자비하게 인터뷰해서 의사결정     │
│               │ 트리를 전부 해소                               │
└───────────────┴────────────────────────────────────────────────┘
```

## 상세 비교

| -------- | ---------------------------- | --------------------------------------------------- | -------------------------------------------------- |
| 복잡도      | 매우 낮음 (11줄)                  | 높음 (6개 페이즈 + 서브시스템)                                 | 중간 (9단계 체크리스트)                                     |
| 대화 방향    | AI → 사용자 (압박 인터뷰)            | AI → 사용자 (압박 인터뷰)                                   | AI → 사용자 (질문)                                      |
| 질문 스타일   | 무자비한 인터뷰, 각 질문에 AI의 추천 답변 제시 | 스타트업 모드: 직접적·불편할 정도로 밀어붙임 / 빌더 모드: 열정적 협력           | 탐색적·협력적, 한 번에 하나                                   |

| 컨텍스트 활용  | 코드베이스 직접 탐색                  | GBrain 캐시 + 이전 세션 + 과거 설계 문서 + Codex second opinion | 프로젝트 파일·커밋 탐색                                      |

| 웹 검색     | 없음                           | 있음 (Phase 2.75 Landscape)                           | 없음                                                 |

| 모드 분기    | 단일 흐름                        | Startup 모드 / Builder 모드                             | 단일 흐름                                              |
| 대상       | 이미 있는 계획/설계의 stress-test     | 제품 아이디어 검증, 스타트업/사이드프로젝트                            | 모든 창의적 작업 (기능 추가, 컴포넌트 등)                          |
| 인프라 의존성  | 없음                           | 높음 (gstack 바이너리, GBrain, Codex 등)                   | 낮음 (로컬 브라우저 서버 선택사항)                               |

## 언제 쓰면 좋은가?

- 아이디어 → 설계가 없음 → **brainstorming** (설계 + 스펙 문서화까지)
- 아이디어 → "이게 가치 있나?" → **office-hours** (YC식 검증, 시장/수요 압박)
- 설계 있음 → "이게 맞나?" → **grill-me** (결정 트리 전체를 한 번에 해소)

## 핵심 차이점 한 줄 요약

- **brainstorming**: "무엇을 만들지" 설계하고 문서로 남긴다
- **office-hours**: "이게 만들 가치가 있는지" 냉혹하게 검증한다
- **grill-me**: "이 계획이 맞는지" 빠르게 압박 테스트한다
