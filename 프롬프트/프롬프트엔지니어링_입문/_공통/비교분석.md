# 프롬프트엔지니어링_입문 비교분석

날짜: 2026-06-15
큰 주제: 프롬프트
참여자: river, kon

---

## 스터디 목적

> **하네스 엔지니어링에서 모델이 바뀌어도 변하지 않는 원칙은 무엇이고, 그것을 우리 작업에 어떻게 적용하는가?**

river의 강점(개념 → 실무 워크플로우 설계)과 kon의 강점(원전 → 불변 원칙 추출)을 하나로 잇는 방향으로 잡았다.

## 오늘의 진행 순서

1. 하네스의 두 축 — 가이드(피드포워드) / 센서(피드백)
2. 불변 5원칙 — kon이 추출한 5개를 river 자료와 교차 검증
3. 변하는 것 — "비계는 줄지 않고 이동한다"
4. 실무 적용 — river의 워크플로우 설계 ↔ kon의 적용표 ↔ 이론적 근거

---

## river 핵심 정리

_공통 「입문가이드」를 출발점으로, **질의응답·소크라테스식 대화**로 자기 이해를 검증한 3부작.

- **입문가이드 질의응답** — "하네스란 무엇인가"를 끝까지 파고들어 핵심 오해 2개를 교정: ① 하네스 ≠ 프롬프트(프롬프트는 하네스의 일부, 하네스 = 모델 뺀 전부) ② 하네스 엔지니어링 = 런타임 서비스가 아니라 에이전트의 개발 환경(개발 방식).
- **하네스 실무적용 — 워크플로우 설계** — 개념을 자기 개발 워크플로우로 직접 설계. `입력 → 라우터(분류) → 전용 워크플로우 → 빌드/컴포넌트 루프 → 게이트` 골격을 도출. 3대 원칙: 불변식은 센서(벽)/취향은 가이드(부탁)+사람 게이트, 경계 안은 자율·경계는 게이트, 거대 트리 금지(라우터+조립).
- **범용 프롬프트 원칙 정리** — 변하지 않는 7원칙 + 보강 원칙. "기법을 외우지 말고 원칙을 이해하라."

특징: **깊이(한 개념을 끝까지) + 자기검증(대화) + 실무 적용(워크플로우)**.

## kon 핵심 정리

**1차 원문(원전)을 직접 읽고** 세 진영을 체계적으로 요약·비교한 5부작.

- **00 개요** — 세 진영(Thoughtworks · Anthropic · OpenAI) 구성 안내.
- **01 Böckeler** — 하네스를 가이드(피드포워드)/센서(피드백) 두 축으로 정의한 개념 프레임워크.
- **02 Anthropic** — 엔지니어링 블로그 4편(2024-12 → 2026-03)을 시간순으로 읽어 가변/불변을 추적.
- **03 OpenAI Codex** — 사람 손코드 0줄로 100만 줄을 만든 대규모 실전 사례.
- **04 종합비교(중점)** — 세 진영을 종합해 변하는 것 vs 변하지 않는 것을 가름.

특징: **폭(여러 원전) + 교차 검증(세 진영 대조) + 시간축 추적(가변/불변)**.

## 핵심 분석

### 안건 1 — 가이드 / 센서
- **kon**은 Böckeler 원전에서 직접 인용해 정리("피드백만 → 같은 실수 반복, 피드포워드만 → 미검증 규칙 → 둘 다 필요").
- **river**는 같은 틀을 대화로 재발견하고 **한 걸음 더** 나아가 배분 원칙까지 도달: *"불변식(절대 규칙)은 센서로, 취향·판단은 가이드+사람 게이트로."*
- 이 배분 원칙은 kon의 OpenAI 문서("불변식을 기계적으로 강제, 취향 불변성은 별도")와 정확히 일치. **river는 대화로, OpenAI는 100만 줄 실전으로 같은 지점에 도달.**

### 안건 2 — 불변 5원칙 교차 검증
kon이 04번에서 명시한 불변 5원칙은 river 자료에 목록은 없어도 곳곳에서 같은 것을 밟고 지나갔다.

| kon의 불변 원칙 | river 자료에서 같은 것 |
|---|---|
| ① 가이드+센서는 한 쌍 | 워크플로우 Q1·Q2 ("부탁 vs 벽") |
| ② 복잡한 일은 잘게 쪼갠다 | 라우터+컴포넌트 루프 / 프롬프트원칙 "분해" |
| ③ 컨텍스트는 유한한 자원 | 입문 Q1 ("관리 = 빼기, context rot") |
| ④ 지식을 에이전트가 읽을 곳에 남긴다 | 입문 Q2-c ("AGENTS.md=목차, 문서 세분화") |
| ⑤ 사람은 핵심 판단으로 | 입문 Q5 심화 ("의도·설계·게이트·래칫") |

한쪽은 **깊이(적용)**, 한쪽은 **폭(검증)** 으로 같은 뼈대를 보강.

### 안건 3 — 변하는 것: 비계의 양·위치
- kon 자료가 강하고 river 자료엔 거의 빈 부분(오늘 river의 최대 수확).
- 모델이 좋아지면 비계의 **양**이 줄지만, 사라지지 않고 **위치**가 "모델 실력의 경계"로 이동. → *"하네스는 줄지 않고 이동한다."*
- kon의 디테일: 이 "이동" 명제는 **Anthropic의 관찰**이고, OpenAI는 오히려 비계를 늘렸으며 일반화를 경고 — **출처별 톤 차이까지 구분**한 것이 04번의 강점.

### 안건 4 — 실무 적용: 세 자료가 한 점에서 만남
- river가 Q5에서 스스로 도출한 **"라우터 구조"** 는 kon이 02번에 정리한 Anthropic 「Building effective agents」의 **Routing 패턴**과, "얇은 오케스트레이터 + 작은 스킬 조립"은 **Orchestrator-workers 패턴**과 정확히 같다.
- 즉 **river는 대화로 워크플로우를 재발명했고, 그 이론적 근거·명칭이 kon 자료에 들어 있다.** 두 자료를 합치면 "내가 만든 구조가 검증된 패턴이었다"는 확인까지 된다.

## 공통점

- 둘 다 핵심 주제를 "하네스 엔지니어링"으로 잡음.
- 둘 다 가이드(피드포워드)/센서(피드백)를 핵심 프레임워크로 봄.
- 둘 다 "원칙은 불변, 기법·비계는 가변"이라는 메타 결론에 도달.
- 둘 다 같은 원전(Böckeler, OpenAI Codex)을 참조.
- 둘 다 "사람은 핵심 판단으로", "센서를 LLM이 읽기 좋게", "애매하면 추측 말고 되물어라"를 실천으로 강조.

## 차이점

| 항목 | river | kon |
|------|-------|-----|
| 출발 자료 | _공통 입문가이드 (2차 가공물) | 1차 원문 직접 (Böckeler/Anthropic/OpenAI) |
| 형식 | 질의응답·소크라테스식 대화, 자기검증 | 구조적 요약 + 비교표 |

## 토론 내용

### 토론 1 — 불변식/취향의 경계를 정하는 주체는?
**river 입장: 사람이 정한다.** "이건 절대 규칙, 이건 취향"이라는 분류 자체가 가치 판단이며, river 자료 Q7의 "재사용 vs fork는 taste 영역, 사람 승인"과 일치. 단, 세 자료 모두 안전장치를 단다 — **에이전트는 경계가 흐릴 때 추측하지 말고 사람을 호출(센서 역할)**. 사람이 정하되, 호출 트리거는 자동화.

### 토론 2 — 한 원칙이 진짜 불변인지 검증하는 더 강한 방법은?
**river 입장: 여러 진영의 교차 검증(kon 방식).** 독립된 출처들이 서로 모르는 채 같은 결론에 이르면 우연이 아니라 구조적 필연. 보강 합의: 세 방법(교차 검증=폭 / 세대 추적=시간 / 반례 탐색=깊이)은 강도 차이가 아니라 보완재이며, kon 자료는 Anthropic 4부작 덕에 교차+시간축을 동시에 잡았고 여기에 river식 반례 탐색을 더하면 3중 검증.

### 토론 3 — 비계 이동 원칙을 워크플로우에 적용 시, 모델 업그레이드 후 가장 먼저 재검토할 것은?
**river 입장: 사람 게이트의 위치.** river 자료의 "사람 게이트도 기계가 먼저 거른 뒤 호출"과 결합하면 검토 순서가 명확해진다 — ① 사람 게이트 중 기계 센서로 강등 가능한 것(양↓) → ② 모델이 새로 어려워진 경계로 사람 게이트 신설(위치 이동). 불변식 센서는 그대로 유지.

### 토론 4 — "센서를 LLM이 읽기 좋게"를 워크플로우 어디에 넣을 때 효과가 가장 큰가?
**river 입장: 컴포넌트 루프의 기계 게이트.** 에이전트가 가장 자주·빠르게 부딪히는 게이트라, 오류 메시지에 수정 지침을 담으면 사람 호출 없이 자가교정 루프가 돈다. 이것이 river가 목표한 "다중 사용자 일관성"의 엔진 — 사람마다 봐주는 게 아니라 산출물이 자동으로 같은 기준에 정렬된다.

## 공동 결론

1. **두 자료는 경쟁이 아니라 상호보완이다.** river는 "깊이·적용", kon은 "폭·검증". 둘을 합치면 river가 대화로 재발명한 구조(라우터=Routing, 조립=Orchestrator-workers)에 kon이 정리한 이론적 근거·명칭이 정확히 들어맞는다.
2. **불변 원칙은 5개로 수렴한다** — ① 가이드+센서 이중 통제 ② 작업 분해 ③ 유한한 컨텍스트 ④ 지식의 외부화(에이전트가 읽을 곳) ⑤ 사람은 핵심 판단으로. 서로 인용 없는 세 진영이 같은 결론에 도달했다는 점이 신뢰의 근거.
3. **변하는 것은 비계의 양과 위치뿐**("줄지 않고 이동한다"). 모델 업그레이드 시 불변식 센서는 두고, 사람 게이트의 양·위치만 재조정하면 된다.
4. **가장 비용 대비 효과 큰 실천 = 센서를 LLM이 읽기 좋게 만들기.** 특히 컴포넌트 루프의 기계 게이트 오류 메시지에 수정 지침을 담는 것이 일관성의 엔진.
5. **다음 학습 후보**(두 자료의 공통 미답 영역): 에이전트 루프(plan→act→observe→repeat)와 Eval — "감싼 것을 어떻게 돌리고 게이트 기준을 어떻게 측정하나".
