# A. 인증

## A1 · SNS 로그인 — `일반회원` · 우선순위 중
- **목적:** 관객이 카카오/구글로 마찰 없이 로그인한다.
- **진입 경로 / 라우트:** `/login` · 헤더 "로그인", 예매 등 인증 필요 액션에서 리다이렉트.
- **구성 요소:** 카카오 로그인 버튼 · 구글 로그인 버튼 · 서비스 로고/소개 · 밴드 로그인 진입 링크(→A3).
- **상태:** 기본 / 진행(OAuth 리다이렉트 중) / **로그인 실패**(취소·오류 메시지) / 이미 로그인됨(→홈 리다이렉트).
- **인터랙션:** 버튼 클릭 → OAuth 시작 → 콜백. 신규면 A2, 기존이면 직전 경로/홈. 실패 시 사유 토스트.
- **연결:** 기능 [F-01](./기능명세서.md#f-01--인증--회원-관리) · loader: 세션 확인 / action: OAuth 콜백 처리.

## A2 · SNS 회원가입 (추가정보 입력) — `일반회원` · 우선순위 중
- **목적:** SNS 최초 로그인 시 닉네임 등 부족한 정보를 1회 받아 일반회원을 활성화한다.
- **진입 경로 / 라우트:** `/signup/complete` · A1 OAuth 콜백에서 신규 사용자일 때 자동 진입.
- **구성 요소:** 닉네임 입력 · (필요) 약관 동의 · 완료 버튼 · SNS에서 받아온 기본정보 미리보기.
- **상태:** 기본 / 검증 에러(닉네임 중복·필수 누락) / 제출 중.
- **인터랙션:** 입력 → 완료 → 회원 생성 후 홈/직전 경로. 이탈 시 미완성 계정 처리(정책).
- **연결:** 기능 [F-01](./기능명세서.md#f-01--인증--회원-관리) · action: 사용자 생성. 입력 Zod 검증.

## A3 · 밴드 회원가입 / 로그인 — `밴드회원` · 우선순위 중
- **목적:** 공연을 운영할 밴드가 아이디/비번 + 밴드명·인스타ID로 가입/로그인한다.
- **진입 경로 / 라우트:** `/band/login`, `/band/signup` · A1의 "밴드로 시작" 링크.
- **구성 요소:** (로그인) 아이디·비번 · (가입) 아이디·비번·밴드명·인스타ID 입력 + **인스타 인증 안내** 문구 · 제출 버튼.
- **상태:** 기본 / 검증 에러(아이디 중복·필수 누락) / 로그인 실패 / 인스타 인증 대기 안내.
- **인터랙션:** 가입 제출 → 밴드 계정 생성(인증 대기) → 인스타 인증 안내. 로그인 → 밴드 대시보드(H1).
- **연결:** 기능 [F-01](./기능명세서.md#f-01--인증--회원-관리) · action: 밴드 계정 생성/세션. argon2id 해시.

# B. 공연 탐색

## B1 · 홈 — 진행 중인 공연 리스트 — `일반/비회원` · 우선순위 **최상**
- **목적:** 곧 있는 공연을 임박순으로 노출해 탐색·예매로 잇는다(서비스 첫 화면).
- **진입 경로 / 라우트:** `/` · 앱 진입 기본.
- **구성 요소:** 공연 카드 리스트(포스터·밴드·일시·장소·티켓가·상태배지) · **정렬: 임박순** · **필터: 지역·장르** · 검색 진입(→B5) · 지난 공연 탭(→B2).
- **상태:** 기본(리스트) / 로딩(스켈레톤) / 빈 데이터(공연 없음) / 에러(재시도).
- **인터랙션:** 카드 탭 → 상세(B3). 필터 변경 → 리스트 갱신. 스크롤 페이지네이션.
- **연결:** 기능 [F-02](./기능명세서.md#f-02--공연-탐색--검색) · loader: 진행중 공연 목록(정렬·필터 쿼리).

## B2 · 홈 — 지난 공연 리스트 — `일반/비회원` · 우선순위 중
- **목적:** 종료된 공연을 아카이브 톤으로 보여준다(회고·밴드 탐색).
- **진입 경로 / 라우트:** `/past` · B1의 지난 공연 탭.
- **구성 요소:** 지난 공연 카드(아카이브 톤·흑백/디밍) · 정렬(최신순).
- **상태:** 기본 / 로딩 / 빈 데이터.
- **인터랙션:** 카드 탭 → 공연 상세(지난, B4).
- **연결:** 기능 [F-02](./기능명세서.md#f-02--공연-탐색--검색) · loader: 종료 공연 목록.

## B3 · 공연 상세 (진행 중) — `일반/비회원` · 우선순위 **최상**
- **목적:** 공연 정보를 보여주고 상태에 맞는 예매 액션을 제공한다.
- **진입 경로 / 라우트:** `/performances/:id` · B1/검색 카드.
- **구성 요소:** 포스터 · 공연 정보(밴드·일시·장소·장르·소개) · 티켓가/잔여 · 입금 안내 · **상태별 CTA**.
- **상태 (5케이스):**
  ① **예매 가능** → "예매하기" 활성(→C1/D1)
  ② **예매 내역 보유** → "내 예매 보기"(→E3/G1)
  ③ **매진** → "매진" 비활성
  ④ **티켓 오픈 전** → 오픈 일시 카운트다운·"알림"(범위 밖이면 안내만)
  ⑤ **지난 공연** → B4로
  + 로딩 / 에러.
- **인터랙션:** CTA 탭 → 케이스별 분기. 비로그인 예매 시도 → 로그인(A1) 또는 비회원 예매(D1) 선택.
- **연결:** 기능 [F-02](./기능명세서.md#f-02--공연-탐색--검색)·[F-03](./기능명세서.md#f-03--예매--결제-무통장입금) · loader: 공연 + (식별 시) 내 예매 보유 여부.

## B4 · 공연 상세 (지난 공연) — `일반/비회원` · 우선순위 중
- **목적:** 종료 공연 정보를 보여주되 예매를 막는다.
- **진입 경로 / 라우트:** `/performances/:id` (status=지난) · B2 카드.
- **구성 요소:** 공연 정보(아카이브 톤) · **비활성 버튼 "예매가 끝난 공연입니다"**.
- **상태:** 기본(비활성 CTA) / 로딩 / 에러.
- **인터랙션:** 예매 버튼 비활성. (밴드 라인업·관람 히스토리 연계 여지.)
- **연결:** 기능 [F-02](./기능명세서.md#f-02--공연-탐색--검색) · loader: 공연 상세.

## B5 · 공연 검색 — `일반/비회원` · 우선순위 중
- **목적:** 키워드로 공연/밴드를 찾는다.
- **진입 경로 / 라우트:** `/search` · 헤더/홈 검색 진입.
- **구성 요소:** 검색 입력 · 최근/추천 키워드(옵션) · 결과 리스트(B1 카드 재활용).
- **상태:** **입력 화면**(초기) / **결과 화면** / **결과 없음**(빈 상태 안내) / 로딩.
- **인터랙션:** 검색 제출 → 결과. 결과 카드 → 상세(B3/B4).
- **연결:** 기능 [F-02](./기능명세서.md#f-02--공연-탐색--검색) · loader: 검색 쿼리 결과.

# C. 예매 & 결제 — 일반회원

## C1 · 예매하기 (폼) — `일반회원` · 우선순위 **최상**
- **목적:** 일반회원이 무통장입금 예매 정보를 입력하고 접수한다.
- **진입 경로 / 라우트:** `/performances/:id/reserve` · B3 "예매하기"(예매 가능).
- **구성 요소:** 매수 선택 · 예매자명 · 전화번호 · 입금자명 · 입금일시 · **계좌번호 + 복사 버튼** · 총 금액(자동계산) · 예매 버튼.
- **상태:** 기본 / 검증 에러(필수·형식·잔여수량 초과) / 제출 중 / 매진 전환(잔여 0).
- **인터랙션:** 매수 변경 → 금액 갱신. 계좌 복사 → 클립보드+피드백. 예매 → **확인 모달(C2/K1)**.
- **연결:** 기능 [F-03](./기능명세서.md#f-03--예매--결제-무통장입금) · loader: 공연·잔여·로그인 예매자 기본값 / action: 예매 생성. Zod 검증, amount 서버 재계산.

## C2 · 예매 확인 팝업 (모달) — `일반회원` · 우선순위 상 (C1의 모달)
- **목적:** 제출 전 매수·금액·예매자·계좌·입금일시를 최종 확인한다.
- **진입 경로 / 라우트:** C1 "예매" 클릭 시 모달(= K1).
- **구성 요소:** 요약(매수·총금액·예매자명·입금계좌·입금일시) · "확인하고 예매" · "수정/취소".
- **상태:** 기본 / 제출 중 / 제출 실패(에러 후 폼 복귀).
- **인터랙션:** 확인 → 예매 확정(입금확인중) → 완료 안내(예매 상세/내역으로). 취소 → C1 복귀.
- **연결:** 기능 [F-03](./기능명세서.md#f-03--예매--결제-무통장입금) · action: C1과 공유. 상세는 [K1](#k1--예매-확인-회원).

## C3 · 문의하기 — `일반/비회원` · 우선순위 중
- **목적:** 예매·공연 관련 문의를 작성한다.
- **진입 경로 / 라우트:** `/inquiries/new` · 공연 상세/마이페이지/푸터.
- **구성 요소:** 문의 종류(카테고리) · 내용 · **공개 여부** 토글 · **(비회원) 비밀번호** · 제출.
- **상태:** 기본 / 검증 에러 / 제출 중 / 완료.
- **인터랙션:** 제출 → 문의 생성 → 내 문의(E6)/안내. 비회원은 비밀번호로 비공개 보호.
- **연결:** 기능 [F-06](./기능명세서.md#f-06--문의-qa) · action: 문의 생성.

# D. 예매 & 결제 — 비회원

## D1 · 비회원 예매하기 — `비회원` · 우선순위 상 (C1 재활용)
- **목적:** 비회원이 가입 없이 예매한다.
- **진입 경로 / 라우트:** `/performances/:id/reserve/guest` · B3에서 비회원 선택.
- **구성 요소:** **C1 폼 전체 + 비밀번호 필드**(조회/취소 인증용) · 비밀번호 확인.
- **상태:** C1과 동일 + 비밀번호 검증 에러.
- **인터랙션:** 제출 → **확인 모달(D2/K2)**. 이후 조회는 D3.
- **연결:** 기능 [F-03](./기능명세서.md#f-03--예매--결제-무통장입금) · action: 예매 생성(guestPasswordHash 포함). C1 폼 컴포넌트 재사용.

## D2 · 비회원 예매 확인 팝업 — `비회원` · C1의 모달 재활용
- **목적:** 비회원 예매 제출 전 최종 확인.
- **진입 경로 / 라우트:** D1 제출 시 모달(= K2, C2와 동일 구조).
- **구성 요소:** C2 요약과 동일(매수·금액·예매자·계좌·입금일시).
- **상태:** 기본 / 제출 중 / 실패.
- **인터랙션:** 확인 → 예매 확정(입금확인중) → 조회 안내(D3 경로·비밀번호 분실 주의).
- **연결:** 기능 [F-03](./기능명세서.md#f-03--예매--결제-무통장입금) · [K2](#k2--비회원-예매-확인).

## D3 · 비회원 예매 조회 — `비회원` · 우선순위 상
- **목적:** 비회원이 자신의 예매를 찾아 상세/QR/취소로 진입한다.
- **진입 경로 / 라우트:** `/reservations/lookup` · 헤더/푸터 "비회원 예매 조회".
- **구성 요소:** **이름 · 전화번호 · 비밀번호** 입력 · 조회 버튼.

- **구성 요소:** **비밀번호 변경** 폼 · 밴드명/인스타ID(읽기전용 + **"변경은 문의 필요"** 안내).

## K2 · 비회원 예매 확인
- **목적/등장:** D1 후속. 비회원 예매 최종 확인(K1과 동일 구조).

## K3 · 예매 취소 확인
