# Q1. 워크플로우 안에서 skill 실행 (grill-me 등)

> 질문: 워크플로우 내에서 필요 시 skill(grill-me 등 gstack/superpowers)을 실행하면 좋겠다. 단 장점이 더 큰 경우에만.

## 답변 요지

- **핵심 긴장:** superpowers·gstack 스킬은 **Claude Code 전용**. 워크플로우에 하드 의존으로 박으면 "아무 에이전트나 붙는다"(Q3) 목표와 충돌(ChatGPT/Gemini엔 grill-me 없음).
- **원칙:** 스킬은 *있으면 가속하는 선택지*로만. **절차 본문은 스킬 없이도 완결.** 이득이 확실히 큰 곳에만.

## 고가치 매핑 (이것만 붙임)

| 워크플로우 | 추천 스킬(있으면) | 이득 |
|---|---|---|
| feature-build 1단계(계획) | brainstorming → grill-me → writing-plans | 잘못된 방향(가장 비싼 실수)을 빌드 전에 차단 |
| route-create 2단계(보안) | security-review / cso | 프로젝트 1순위 보안의 독립 검토 |
| bug-fix 1~2단계 | systematic-debugging / diagnose | "재현 먼저·근본원인" 규율 강제 = 우리 절차와 일치 |
| 공통 종료(PR 직전) | requesting-code-review / codex | 머지 전 독립 리뷰 게이트 |

- component-create엔 **의도적으로 안 붙임**(TDD·시각검수 이미 내장 → 스킬 추가 이득 작음).

## 박는 방식 (이식성 보존)
각 워크플로우 상단 한 줄:
> `> 추천 스킬(에이전트가 지원하면): brainstorming → grill-me. 없으면 아래 절차만으로 진행.`
→ Claude Code에선 가속, 타 에이전트에선 무시되어 이식성 유지.

## 사용자 재정의 (중요)
- 의도는 "스킬을 무작정 넣어라"가 아니라 **"워크플로우에 빠진 단계가 있느냐"**.
- 발견된 구멍: `feature-build`가 1단계부터 "계획·쪼개기" → **기능이 완벽히 정의됐다고 가정.** 라우터가 "기능 추가"로 보낸 시점엔 적합성·범위 미정인 경우가 대부분. start.md의 "기획·디자인 완성 후" 전제가 만든 누락.

## 수정 방향 (확정 후보)
**feature-build에 0단계: 기능 정의 & 검증 게이트 신설**(계획·쪼개기 앞):
- 적합성(현 프로젝트에 필요한가) → 범위·수용기준 합의 → 산출물 `docs/specs/<기능>.md`.
- 스킬 훅(여기서 진짜 이득): `grill-me`(합의 끌어내기), `to-prd`(정의서 산출). 없으면 구조화 Q&A.
- 게이트: "개발 가능 수준"이 될 때까지 빌드 진입 금지(불충분하면 사용자와 반복).
- **Q7(성숙도 3분기)과 동일 축:** 아이디어만→0단계 무겁게 / 기획만→적합성·범위만 / 기획+디자인→가볍게 확인 후 빌드.

## 결정 (확정)
- ✅ feature-build에 **0단계: 기능 정의 & 검증 게이트** 신설, 거기에만 grill-me/to-prd 훅(있으면 사용).
- ✅ 나머지 워크플로우의 스킬 훅은 **보류**(이번 핵심 아님).
- ✅ **상세 설계는 Q7**(성숙도 3분기: 아이디어만/기획만/기획+디자인)에서 0단계와 함께 한꺼번에.
