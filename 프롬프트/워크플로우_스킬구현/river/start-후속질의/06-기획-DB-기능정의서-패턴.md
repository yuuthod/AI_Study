# Q6. 기획·DB·기능정의서 첨부 패턴

> 질문: 이후 기획에 맞춰 DB·기능정의서를 첨부해 작업할 텐데 관련 내용이 없다. 없다면 어떤 md를 만들어 공유할지, 초기 실행 시 패턴을 통일하는 게 좋을지?

## 결론
- 현재 없음 → **초기에 입력 문서 체계 + 템플릿을 생성해 패턴 통일**(여러 사람이 비슷한 기획 문서).
- Q1(정의 게이트)·Q7(성숙도 분기)와 직접 연결.

## docs/ 입력 문서 체계 (초기 생성)
```
docs/
  specs/        기능 정의서(PRD). 정의 게이트 산출물=빌드 입력. _template.md + <기능>.md
  data-model/   엔티티·관계·비즈니스 규칙(기획 수준). _template.md
  adr/          (선택·래칫) 아키텍처 결정 기록
```

## 기능 정의서 _template.md (경량 1페이지)
목적/배경 · 사용자·시나리오 · 범위(In/Out) · 수용기준(체크 가능) · 필요 데이터 · UI 참조 · 비고.

## 드리프트 방지 규칙
- 기획 문서=왜(business), prisma/schema.prisma=어떻게(impl). **DB 진실원천=Prisma.**
- data-model 문서는 의도·규칙만, 구현 세부는 Prisma 단독 출처.

## 작동
사용자가 기획 첨부 → 에이전트가 _template 형식으로 정리/사용자 작성 → feature-build 0단계가 읽고 검증 → 빌드. 전 기능 동일 양식.

## 확인 대기 (사용자)
- 데이터 모델 문서화: 별도 기획문서 / Prisma 단독(주석+자동 ERD) / 둘 다.

## 반영
- 마지막 일괄: docs/specs/_template.md, docs/data-model/_template.md 생성, AGENTS.md·naming에 위치 규칙, feature-build 0단계가 specs 참조.
