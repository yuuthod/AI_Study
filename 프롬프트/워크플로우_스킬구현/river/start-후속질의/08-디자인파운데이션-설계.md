# [C] 디자인 파운데이션 설계

> 질문: 껍데기(start 빌더) 이후 실제 개발 전, 디자인 트랙(시안→토큰→글로벌→프리미티브→페이지)을 어떻게 꾸리나. design-foundation 워크플로우 설계.

## 확정 (6문항)
| # | 항목 | 결정 |
|---|---|---|
| C-Q1 | 토큰 파이프라인 | **수동 미러링 시작 → Tokens Studio+Style Dictionary 자동화 래칫** |
| C-Q2 | 토큰 계층 | **2계층(원시→의미) + 컴포넌트 토큰 래칫** + 네이밍 규약(--color-* 등) |
| C-Q3 | 글로벌 스타일 | **modern-normalize + 합리적 기본** + 핵심 mixins(focus-ring·media·visually-hidden·truncate) |
| C-Q4 | 프리미티브 | **에센셜 선행 + 시안 반복요소 우선** (Box·Stack·Container·Text·Heading·Button·Input·Field), 기능 컴포넌트는 창발 추출 |
| C-Q5 | 완료 게이트 | **경량 blocking**(기계: 렌더·a11y·토큰lint / 사람: Storybook 시안대비 1회) → 페이지 진입 |
| C-Q6 | 배치 | **별도 design-foundation.md + 라우터 버킷**, kickoff가 호출, 리테마링 재진입 |

## 핵심 원리
- 디자인 = **반복 갱신 트랙**(1급 시민) → 독립 워크플로우로 재진입 가능(색·테마·다크모드 변경).
- 순서: 토큰 먼저 → 프리미티브 먼저 → 페이지. "컴포넌트 먼저 vs 페이지 먼저"는 **하이브리드**(프리미티브 선행 + 기능 컴포넌트 창발).
- 성숙도 연동: 디자인 있으면 실값 모드, 없으면(아이디어/기획만) 중립 임시값 모드.

## 반영된 파일
- 신설: `docs/workflows/design-foundation.md`
- 수정: `AGENTS.md`(라우터 버킷), `project-kickoff.md`(3경로가 호출), `_shared/tokens-and-style.md`(네이밍·파이프라인·글로벌 확장), README(7워크플로우).

## 현재 파일 관리 경계 (재확인)
- 관리: 개발 전부 + 기획/디자인 문서 거버넌스 + 토큰 구조 + 디자인 파운데이션 절차.
- 입력으로만: 기획 내용·디자인 시안·Figma(외부 도구).
- 래칫(나중): Figma 자동연동, 다크모드 구현, 배포/모니터링.
