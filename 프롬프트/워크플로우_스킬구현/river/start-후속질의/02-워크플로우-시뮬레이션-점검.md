# Q2. 워크플로우 실행 시뮬레이션 → 마찰/누락 점검

> 질문: 각 워크플로우를 실제로 실행하는 시뮬레이션을 거쳐 불편하거나 추가로 필요한 로직이 없는지 확인.

## 시뮬레이션: "회원 프로필 수정 기능 추가"
1. 라우터→feature-build. 계획·쪼개기 단계에서 **계획 문서 출력 위치 미지정**, 0단계(정의·검증) 부재.
2. "프로필 update action"→route-create. 두 곳에서 막힘:
   - **DB 스키마 변경 시 prisma migrate 단계 없음.**
   - **RR7 라우트 등록(app/routes.ts) 단계 없음.**
3. UI 단위→component-create. 큰 마찰 없음(표현 컴포넌트의 "테스트 먼저"만 다소 형식적).

## 점검 결과

| 심각도 | 워크플로우 | 누락/마찰 | 처방 | 처리 |
|---|---|---|---|---|
| 高 | feature-build | 0단계(정의·검증) 부재 | 정의 게이트 신설 | **Q1 확정** |
| 高 | route-create | DB 스키마 변경 시 Prisma migrate 단계 없음 | 스키마수정→migrate dev→확인 단계 추가 | 본 질문에서 반영 |
| 高 | route-create | RR7 라우트 등록(app/routes.ts) 단계 없음 | 라우트 파일+routes.ts 등록 명시 | 본 질문에서 반영 |
| 中 | feature-build | 계획/정의 문서 출력 위치 미표준 | docs/specs/<기능>.md 표준화 | **Q6 연결** |
| 低 | route-create | rate-limit 공용 유틸 없음 | app/lib/rate-limit.server.ts 스텁 | 선택 |
| 低 | component-create | 표현 컴포넌트 "테스트 먼저" 형식적 | "행동 있으면 테스트 먼저, 순수 표현은 스토리 우선" 완화 | 선택 |
| 低 | 전체 | 커밋 전 절차(훅 강제) 미명문 | 워크플로우에 명문화 | **Q4 연결** |

## 결정 상태
- 高 2건(route-create의 migrate + 라우트 등록)은 **반드시 반영** 필요.
- 사용자 확인: 지금 route-create를 수정할지, 다른 질문들과 함께 마지막에 일괄 반영할지.
