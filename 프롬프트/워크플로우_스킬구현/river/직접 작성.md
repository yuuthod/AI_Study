

너는 10년차 AI 전문가이자 현 프로젝트의 PL이다.
실무 개발자는 2년차, 5년차 프론트엔드 두명으로 AI agent 사용을 기본으로 프로젝트 개발을 진행하려고 한다. 실무자의 특성상 백엔드 보안에 유의하며 프로젝트를 세팅하여야 하고, 하네스 엔지니어링으로 프로젝트를 진행해야한다. 다음은 프로젝트를 시작하기 전 설정하기 위한 초기 파일들을 먼저 만든다. 해당 파일들은 프로젝트 내부에 들어가있는 파일이 아닌 프로젝트가 설정된 이후엔 삭제되어야 하는 파일이며, 다른 프로젝트의 설정에도 사용할 수 있어야 한다. 예상하는 작업 흐름은 다음과 같아. start.md 파일을 작업 폴더 내부에 복사 붙여넣기 한 후 ai agent를 실행시켜. 'start.md 파일을 기반으로 프로젝트 생성해줘.' 하면 당장 실무 개발을 진행할 수 있을 정도의 프로젝트를 생성한다.

모든 스펙은 한질문에 하나씩 확인하고 넘어가야하며, 질문할 때에는 스펙이름 뿐만이 아닌 왜 해당 스펙이 좋은지에 대한 장단점을 작성하여 사용자로 하여금 충분히 고민하고 넘어갈 수 있도록 해야한다.
결론이 나지 않는 경우 반복적으로 질문할 수 있어야 하며, 문제가 될 수 있는 부분은 100% 확인이 될때까지 역질문으로 진행해야한다.
### 원하는 결과물
- 기획, 디자인을 완성한 이후 프로젝트를 실행할 때 질문 없이 프로젝트 초기 설정을 한번에 진행할 수 있는 md 파일
	- 스펙 설정: react-dom(remix), typescript, git 등
	- 제약: 린트, git husky 등
	- 아키텍처: 디자인패턴, 폴더 구조 등
	- 보안 관련: 보안을 위해 사용해야 하는 개발 패턴 등
	- 스타일: sass, cdd module, font family, color 변수 설정 등
	- 프로젝트에서 하네스 엔지니어링을 위한 md 파일을 워크플로우에 기반하여 작성하여야 한다. 예를 들어 컴포넌트를 개발하려고 한다면, AI agent는 docs/component/create.md 파일을 첨부해 진행할 수 있도록. 잘게 쪼개되 하나의 작업에 하나의 md파일만 가져가 사용할 수 있도록 혹은 필요하다면 자잘한 md파일을 여러개 첨부할 수 있도록. 최대한 작업이외의 md 파일을 첨부하지 않을 수 있게 분류해야한다.
- 프로젝트 워크플로우기반 md 파일
	- 해당 프로젝트에서 개발 진행시 여러 사람이 진행하더라도 유사한 코드가 나오도록 작업 플로우를 지정한다. (@프롬프트/프롬프트엔지니어링_입문/river 의 md 파일 참고)

확인해야할 것.

- 워크플로우 내에서 필요한 경우 skill을 실행했으면 좋겠어. grill-me 등 맷포콕의 스킬이나 superpowers 중 추가적으로 있다면 장점이 더 큰 경우에만
- 각 워크플로우 파일들을 실제로 실행시켜 보는 시뮬레이션을 거친 후 불편해보이거나 추가적으로 필요해보이는 로직은 없는지 확인해줘
- 프로젝트를 실행했을 때 어떤 ai agent 든 잘 붙을 수 있는지 확인해줘. 예를 들어 chatGPT나 gemini등은 AGENT.md 파일을 기본으로 하고 claude는 CLAUDE.md를 기본으로 한다면 AGENT.md 파일에 기본값을 작성하고, CLAUDE.md에는 AGENT.md 파일을 참고해야한다 는 글이 적혀있던 어쨌든. 사용자가 굳이 명령하지 않아도 모든 agent가 같은 내용을 기본적으로 숙지한 후 뭐든 진행할 수 있도록
- 브랜치 포맷? 어떤식으로 브랜치를 생성하는지, 커밋 포맷? 어떤 형태로 커밋하는지 예시 작성. 또한 커밋하기 전 절차가 어떻게 되는지 (husky를 설치했으니 강제된 내용이 있을 것. 테스트코드를 실행시켜 반드시 전부 통과해야 한다던지 등)
- vscode를 통해 개발코드를 확인할텐데 prettier가 각 IDE에서 다르게 동작하지 않도록 강제할 수 잇는 방법이 있는지 (예를 들어 줄간격이나 탭위치 등등)
- 이후 기획에 맞춰 DB나 기능정의서 등을 첨부해서 작업을 진행할 것 같은데 해당 내용은 없는지? 없다면 어떤식으로 md파일을 만들어 공유하면 좋을지. 초기 실행시 이것또한 패턴을 일치시키는게 좋을지?
- 초기 설정 이후 두번째 스탭을 어떻게 진행할지?
	- 기획도 없고 아이디어만 있는 경우 (기획이 완성되지 않은 경우)
	- 기획만 있는 경우
	- 기획과 디자인 모두 있는 경우
