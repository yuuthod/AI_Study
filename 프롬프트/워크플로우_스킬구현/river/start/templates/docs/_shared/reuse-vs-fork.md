# 공유: 재사용 vs 조합 vs fork 판단

> 정답 없는 **taste 영역**. 결정적으로 못 박지 않고, 아래 휴리스틱 + 센서 + 사람 게이트로 분담한다(river Q7).

## 핵심 기준
- **"같은 이유로 함께 변할 것"** 이면 → **재사용**.
- **"지금 우연히 비슷할 뿐, 다른 이유로 변할 것"** 이면 → **fork**.
- UI 차이(variant/size/color 같은 *보이는 변형*)는 fork 사유가 **아니다** → props로 흡수.

## 냄새 신호 (🚩 = fork/조합 신호)
- 🚩 *동작을 분기시키는* boolean이 늘어남(`isModal`, `asLink` …). boolean 하나당 복잡도 ≈ 2배.
- 🚩 props 20개 괴물 + if 범벅 → 모든 호출처가 엮여 A 고치면 B·C 깨짐.

## 우선순위
1. **fork보다 composition 먼저.** 베이스는 멍청·범용으로 두고, 특수 동작은 *감싸는* 새 컴포넌트로.
2. **Rule of Three** — 3번째 등장에서야 추상화.
3. **잘못된 추상화보다 중복이 싸다**(Sandi Metz).
4. 디자인 시스템 프리미티브 = 적극 재사용 / 기능 컴포넌트 = 조합 위주.

## 분담 (삼분할)

| 센서(자동) | props 개수/복잡도 lint 임계값, 기존 컴포넌트 테스트로 회귀 차단 |
