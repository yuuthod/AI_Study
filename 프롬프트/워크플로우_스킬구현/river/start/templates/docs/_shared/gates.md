# 공유: 게이트 기준 (기계 vs 사람)

> river 모델: **경계 안은 자율(안 멈춤), 경계선에서 게이트. 사람은 양 끝에만. 기계가 먼저 거른 뒤 사람을 부른다.**

## 기계 게이트 (자동 — 사람 안 부름)
- 타입체크 통과 / ESLint 통과 / 단위 테스트 통과 / 컴포넌트 렌더·a11y 통과 / 빌드 통과.
- **실패 시 사람을 부르지 않고 에이전트가 고친다.** "최소한 돌아간다"를 기계가 보장.
- 안 보이는 작업(loader/action/유틸)은 **기계 게이트가 곧 최종 게이트**다.

## 사람 게이트 (사람만 판단 가능한 것)
- **설계 게이트(앞):** "이 계획·구조로 갈까?" — 큰 작업 시작 전.
- **시각 게이트(뒤):** "의도대로 보이나?" — Storybook에서 보이는 컴포넌트/화면만.
- **하네스 변경 승인:** 워크플로우·센서를 바꿀 때(`workflow-change`).
- 규칙: **보이는 것/판단이 필요한 것만 사람.** 그 외엔 자동 통과.

## 순서 (고정)
```
개발 → [기계] 타입·lint·테스트·렌더 OK? ─실패→ 에이전트가 고침
                     └─통과→ [사람] "보기 좋나 / 의도대로인가?"
```
사람 시간이 가장 비싸다. 기계 통과 전에는 사람을 부르지 않는다.
