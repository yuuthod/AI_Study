# 워크플로우: 버그 수정 (bug-fix)

> 빌드 플로우와 다르다. **재현이 먼저.** 근본 원인 없이 고치지 않는다.
> @참조: `_shared/gates.md` · (서버/보안 버그면) `_shared/security-checklist.md`

## 1. 재현 (Reproduce)
- 버그를 **실패하는 테스트로** 먼저 고정한다. 재현 안 되면 고칠 수 없다 → 정보 더 요청.

## 2. 근본 원인 (Root cause)
- 증상이 아니라 원인을 찾는다. 추측 금지, 로그/실측으로 확인.

## 3. 최소 수정 (Fix)
- 원인만 고친다. 주변 리팩터를 섞지 않는다(섞으면 `refactor:` 별도 작업).

## 4. 회귀 방지 (Regress-test)
- 1단계의 실패 테스트가 **통과로 바뀌는지** 확인. 그 테스트를 영구 보존(회귀 차단 = 래칫).

## 5. 게이트 & 종료
- `pnpm typecheck && pnpm lint && pnpm test` 통과.
- `fix:` 커밋 → PR → CI 통과.

## 하지 말 것
- 재현 테스트 없이 "고친 것 같다"로 종료, 원인 모른 채 증상만 가리기, 버그 수정에 무관한 변경 끼워넣기.
