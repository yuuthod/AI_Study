# 워크플로우: 워크플로우 자체 수정 (workflow-change) — 메타

> 하네스(이 문서들·`AGENTS.md`·`docs/README.md`·센서 규칙)를 바꾸는 작업. **하네스의 진화는 사람이 승인한다(래칫).**
> 모델은 순응적이라, 규칙을 바꾸는 행위 자체에 사람 게이트가 없으면 불변식이 슬그머니 풀린다.
> @참조: `_shared/gates.md`

## 언제 여기로 오나
- 새 워크플로우 문서 추가(예: `refactor.md`, `component-modify` 분리).
- 라우터 분류 변경, 불변 규칙(센서) 추가/완화, lint·CI·훅 규칙 변경.
- **같은 부류의 실수·리뷰 지적이 2번 반복될 때**(`docs/friction-log.md`의 2회차) — 규칙·센서로 **승격**한다. 1번은 그냥 고치고, **2번째에 박는다.** 가능하면 `AGENTS.md` 한 줄보다 lint·테스트로 **기계화**(그래야 3번째는 사람 아닌 센서가 막는다).

## 절차
1. **무엇을·왜** 바꾸는지 한 단락으로 명시(어떤 반복/마찰이 이 변경을 정당화하나).
2. 변경을 **별도 브랜치/PR**로. 절대 다른 기능 작업에 섞지 않는다.
3. **센서를 *완화*하는 변경이면** 추가 정당화 + 명시적 사람 승인 필수(벽을 낮추는 것이므로).
4. **센서를 *강화*하는 변경(새 lint 룰·커버리지 상향)**은 환영 — 단 기존 코드가 통과하는지 확인.
5. 문서/규칙 변경이 `AGENTS.md` 라우터 표와 일치하는지 확인.
6. **`AGENTS.md`를 고쳤으면 `CLAUDE.md`·`GEMINI.md` 포인터가 여전히 AGENTS.md를 가리키는지 동기 확인**(진실원천 1곳 유지).

## 게이트 & 종료
- 사람 리뷰 승인(필수) + CI 통과.
- `chore:` 또는 `docs:` 커밋. 한 번 더해진 규칙은 **되돌리지 않는 것을 기본**으로(래칫).
- 마찰 로그발(發) 승격이면 `docs/friction-log.md`의 해당 항목을 `## 닫힘(승격)`으로 옮기고 무엇으로 기계화했는지 적는다.

## 하지 말 것
- 기능 작업 도중 슬쩍 규칙 끄기, 승인 없이 센서 완화, 거대 트리식으로 모든 경우를 미리 추가(필요해질 때 하나씩).
