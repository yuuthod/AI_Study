# 맷포콕_5가지스킬 비교분석

날짜: 2026-06-12
큰 주제: 프롬프트
참여자: river, kon

---

## river 핵심 정리

**6개 스킬을 다루며 "큐레이션의 메타분석"에 집중.** (총 10개 파일)

- 각 스킬마다 원문 + 번역 + 해설을 정리한 뒤, 추가로 메타·생태계까지 확장.
- 다룬 스킬: `grill-me`, `to-prd`, `to-issues`, `tdd`, `improve-codebase-architecture`, `diagnose`.
- **핵심 발견 — "5가지"는 출처마다 다르다**: river 영상 노트(…diagnose…)와 aihero.dev(…to-issues…)의 5번째 슬롯이 갈림. 모순이 아니라 프레이밍 차이로 규명(`08_라인업차이.md`). 그래서 6개를 모두 다룸.
- 구조를 **선형 본류 + 분기**로 도식화: `grill-me→to-prd→to-issues→tdd→improve-arch` 본류 + `diagnose`는 막혔을 때 빠지는 우회로.
- 관통 철학: **"AI를 더 똑똑하게 만들지 않는다. AI가 그냥 두면 건너뛸 단계만 정확히 느리게 만든다."**
- 인기 이유(바이브 코딩 안티테제, 의도적 마찰, 정렬 실패 정조준)와 스킬 마켓플레이스·최신 동향까지 외부 조사로 확장.

## kon 핵심 정리

**5개 스킬을 "원문 정밀 정독".** (총 7개 파일)

- 다룬 스킬: `grill-me`, `grill-with-docs`, `tdd`, `diagnose`, `to-prd`.
- 본문뿐 아니라 **부속 파일 전체**를 번역: tdd의 `deep-modules.md`/`tests.md`/`mocking.md`/`interface-design.md`/`refactoring.md`, grill-with-docs의 `CONTEXT-FORMAT.md`/`ADR-FORMAT.md`.
- 종합비교에서 **4가지 공통 원칙** 도출: ① 겉으로 드러나는 동작 검증 ② 한 번에 하나씩 ③ AI가 먼저 답 내고 검증받기 ④ 정한 용어·결정을 문서로 남기기.
- 구조를 **계획 단계 / 실행 단계** 두 갈래로 정리: 계획(grill-me, grill-with-docs) / 실행(tdd, diagnose, to-prd).
- **7가지 분석 렌즈**(쓸 때·막으려는 실수·부속 파일 역할·딴 길 차단 장치·결과물 형식·말투·맞물림)로 스킬별 핵심을 해부. 빈칸도 "왜 없는지"를 적어 성격을 드러냄.

## 공통점

- **다룬 스킬 4개 겹침**: `grill-me`, `to-prd`, `tdd`, `diagnose`.
- **공통 원천 사상**: 둘 다 *깊은 모듈(deep module)* — 존 오스터하우트 *A Philosophy of Software Design* — 을 스킬군을 관통하는 축으로 지목.
- **행동(behavior) 검증**: "코드는 통째로 바뀌어도 테스트는 안 바뀐다"를 tdd의 핵심으로, to-prd·diagnose에도 동일 사상이 흐름을 공통 인식.
- **"한 번에 하나씩 + 추천/순위 제시"** 패턴을 grill·tdd·diagnose 공통 메커니즘으로 파악.
- **공유 기반 = `CONTEXT.md`(용어집) + `docs/adr/`(결정 기록)**: 한 스킬이 만들고 다른 스킬이 가져다 쓰는 구조라는 결론에 양쪽 모두 도달.
- **닫힌 워크플로우**: 개별 스킬이 따로 노는 게 아니라 하나의 파이프라인으로 맞물린다는 결론 일치.
- 둘 다 지난 스터디(`유사스킬_프롬프트비교`) 결론("하네스가 적을수록 깊게 판다", "길이≠품질")을 인용해 연속성 확보.

## 차이점

| 항목 | river | kon |
|------|-------|-----|
| 다룬 스킬 수 | 6개 | 5개 |
| 고유 스킬 | `to-issues`, `improve-codebase-architecture` | `grill-with-docs` |
| 접근 방식 | 넓게 — 메타·인기·생태계까지 확장 | 깊게 — 부속 파일 원문까지 정독 |
| "5가지" 해석 | 출처마다 다른 **큐레이션**으로 메타분석 | grill-with-docs 포함한 **제3의 5개** 선택 |
| 워크플로우 도식 | 선형 본류 + 분기(diagnose=우회로) | 계획 단계 / 실행 단계 2갈래 |
| 분석 틀 | 인기 이유 6가지 + 라인업 차이 | 7가지 분석 렌즈 + 4가지 공통 원칙 |
| 부속 파일 | 본문 위주(부속은 언급 수준) | deep-modules·tests·mocking·CONTEXT/ADR-FORMAT 전부 번역 |

> 메타 발견: river가 "5가지는 출처마다 갈린다"고 정리했는데, **kon의 5개 선택(grill-me·grill-with-docs·tdd·diagnose·to-prd)은 river가 든 두 라인업 어디에도 정확히 안 맞는 제3의 큐레이션**이다. river의 주장이 kon의 선택에서 그대로 실증된 셈.

## 토론 내용

**Q1. 스킬 선택 차이 — river는 to-issues·improve-arch를 넣고 grill-with-docs를 뺌, kon은 정반대.**
→ river: **"둘 다 맞고 관점 차이다."** river는 '영상/aihero 두 공식 출처'의 라인업을 따랐고 grill-with-docs는 거기 없어 제외, kon은 출처보다 스킬 자체의 중요도(CONTEXT/ADR 공급원)로 선택. 이는 river가 `08_라인업차이.md`에서 내린 "둘 다 맞다"는 결론과 일관.

**Q2. 깊이 vs 넓이 — kon은 부속 파일까지 정독, river는 메타까지 확장. 왜 넓게 갔나?**
→ river: **"각 스킬별 원문·번역·핵심포인트를 다 조사한 후 그 외 부분까지 조사한 것이라 깊이가 부족하다고 보지 않는다."** 즉 river는 '기본 깊이 + 확장', 차이는 kon이 **부속 파일**까지 파고든 지점. 둘을 합치면 빈칸이 메워지는 상보 관계.

**Q3. 실전 적용 — 어느 지점부터 도입할까?**
→ river: **"grill-me 단독부터."** 가장 가볍고(11줄) 의존성 없이 즉시 체감 가능. river가 지난 스터디에서도 grill-me를 가장 인상적이라 꼽은 것과 일관된 현실적 진입점.

## 공동 결론

1. **"5가지"는 정전(canon)이 아니라 큐레이션이다.** river의 메타분석(출처마다 갈림)이 kon의 제3 라인업 선택으로 실증됐다. 같은 저장소를 봐도 무엇을 본류로 끌어올리느냐에 따라 5개가 달라진다 — 1차 출처 교차검증의 중요성.

2. **두 정리는 경쟁이 아니라 상보다.** river=넓이(워크플로우 전경·생태계·인기), kon=깊이(부속 파일·형식 템플릿·분석 렌즈). river의 6개 본문 + kon의 부속 파일 정독을 합치면 SKILL.md 표층부터 보조 문서까지 완결된 그림이 된다.

3. **스킬군의 단일 철학 = "느림을 통한 정렬".** 양쪽 모두 깊은 모듈·행동 검증·한 번에 하나씩·공유 문서(CONTEXT/ADR) 기반을 공통 축으로 도출. 개별 스킬은 "AI가 건너뛸 단계"에 마찰을 박아넣는 장치이며, 닫힌 워크플로우로 맞물린다.

4. **실전 진입점은 grill-me 단독.** 전체 파이프라인 도입은 비현실적이므로, 의존성 없는 grill-me로 "정렬 실패 방지" 효과부터 체감하고 점진 확장하는 것이 합리적.
